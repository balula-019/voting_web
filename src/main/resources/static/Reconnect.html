State Transition Diagram

LOST_SUBMITTED → (admin approves) → ADMIN_APPROVED_LOST
FOUND_SUBMITTED → (admin approves + chat) → ADMIN_APPROVED_FOUND
Admin manually links approved lost & found → MATCH_PENDING → (admin confirms after verification) → MATCH_CONFIRMED
Police receives item → POLICE_RECEIVED_ITEM
Police generates control number → PAYMENT_PENDING
Lost user pays (via control number) → PAYMENT_CONFIRMED
Police hands over item → HANDOVER_COMPLETED → CLOSED

Fraud Prevention & Edge Cases

  • Only admin can approve items after verifying images/descriptions.
  • Found user must chat with admin to prove legitimacy.
  • Multiple claims on same item: admin chooses one match, others are rejected.
  • Dispute resolution: user can flag; admin investigates using audit logs.
  • Trust score increases by +5 for successful recovery, -10 for fake report.
  • Police verify ID before handover.

Monetization & Scalability

1000 TZS per successful recovery. Partnerships with government for nationwide rollout. Use cloud functions for async matching, CDN for images, read replicas for high traffic.

Security & Compliance

All images scanned for inappropriate content. HTTPS, audit trails, role-based access control. Data encryption at rest. Compliance with local data protection laws.
